# GitBrain frontend

Next.js 16 (App Router) + TypeScript + Tailwind v4. This is **Phase 3**: the app
shell, auth, and project/repository management UI — wired to the real Phase 2
backend, not mocked. Chat, the knowledge-graph viewer, the code explorer, and search
depend on backend work that doesn't exist until Phases 4-8, so they aren't in this
phase; the repository detail page says so directly instead of faking them.

## Local setup

```bash
cp .env.local.example .env.local   # point API_BASE_URL at your running backend
npm install
npm run dev
```

Requires the Phase 2 backend running (`docker compose up` in `../backend`) — including
the `GET /users/me` endpoint added alongside this phase, which the session check
below depends on.

## How auth works here

Tokens live in httpOnly cookies, not localStorage — a Server Action sets them after
login, so client-side JavaScript never touches the raw JWT. `proxy.ts` (Next.js 16's
replacement for `middleware.ts` — the file convention was renamed in the 16.0
release) redirects unauthenticated visitors before a protected route renders, and
proactively refreshes the access token when it's about to expire.

`proxy.ts` is a UX fast path, not the actual security boundary: every protected
layout also calls `requireSession()` (`src/lib/api.ts`), which hits FastAPI's own
`/users/me` and relies on FastAPI's `get_current_user` dependency to enforce the real
check. Next.js middleware/proxy bypass vulnerabilities have shipped before (a
segment-prefetch auth-bypass issue was patched in a 2026 security release); this way
a bypassed or misconfigured proxy still can't render another user's data, because the
backend refuses the request regardless of what the frontend thinks happened.

## Design

Palette (a warm-paper/charcoal/brass "index card" system, not the cream+terracotta
or dark+neon looks most AI-assisted UI defaults to), type (Space Grotesk + JetBrains
Mono), and the repository status trail are deliberate choices tied to what GitBrain
actually is — an indexed record of a codebase. The status trail in particular renders
`IndexingStatus` as its literal position in the Phase 1 ingestion pipeline rather
than an isolated badge, because the order is real information here.

## Known gaps

- `components.json` is hand-written, not generated by `npx shadcn@latest init` (no
  network access in the environment that built this) — the aliases and CSS paths are
  correct for this project, but re-run `init` or `add` if the exact style/schema
  values matter to you.
- No dark-mode toggle yet, though the CSS variables for it are already defined in
  `globals.css`.
- Session role-gating in the UI (hiding reindex/delete for viewers) is convenience,
  not security — the backend enforces RBAC independently either way.
